# TPS Watchlist 0.2.6

TPS Watchlist `0.2.6` is a backward-compatible scheduler performance and reliability patch. It replaces four chained collection traversals with one ordered pass and validates each due watch once.

## Changes

- Combine active/due filtering, invalid-definition counting, first-five warning-path collection, and valid-definition collection in one traversal.
- Preserve the released valid-watch order, draft-warning count and path order, scheduler guards, batch reason, and due-only flag.
- Remove the full intermediate due-row and invalid-row arrays.
- Add focused regression coverage for inactive, not-due, valid, and invalid watches.
- Add no cache, state, fallback, retry, monkeypatch, timer, listener, persisted field, unsupported API, setting, command, or migration.

## Before/after evidence

- Exact public `0.2.5` and the candidate actual runtime methods matched across 1,000 seeded scenarios containing 151,599 rows, with zero selected-output or warning-payload mismatches.
- The corpus included active and inactive rows, empty, past, and future check timestamps, and valid and invalid watch definitions.
- On a 20,000-watch due fixture containing 13,333 valid and 6,667 invalid definitions, validation calls fell from 40,000 to 20,000.
- Across 51 interleaved actual-method rounds, median selection time fell from 4.162 ms to 0.731 ms (82.44%) and p95 fell from 5.070 ms to 1.297 ms (74.42%).
- The minified production bundle shrank from 56,691 to 56,645 bytes.

The benchmark isolates scheduler selection. Watch discovery, provider requests, concurrency, state persistence, events, notifications, dashboard rendering, commands, settings, and integrations are unchanged.

## Validation

- Exact public `0.2.5` was pinned at commit `b51e39502764ef048e846e09d3deb3ee32248d54`.
- The untouched baseline passed all 30 core tests, four settings contracts, TypeScript, and its production build with runtime deployment suppressed.
- The new scheduler regression passed against both the exact released implementation and the candidate.
- Final versioned `0.2.6` passed all 31 core tests and four settings contracts, TypeScript, the full declared test command, and a separate production-mode build.
- The final artifacts deployed byte-identically only to the registered Obsidian Plugin Test Vault.
- Obsidian 1.12.7 reloaded the isolated test vault and registered Watchlist commands without creating a watch or invoking **Check all**.
- Runtime-owned `data.json` remained absent and `.hotreload` remained unchanged. Production was not accessed.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- Providers, conditions, watch definitions, settings, stored state, scheduler cadence, events, notifications, integrations, and public APIs are unchanged.
- No settings or data migration is required.
- Watchlist still monitors only while the authorized desktop app is running; this release does not add background execution.
