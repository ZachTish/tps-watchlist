# TPS Watchlist 0.2.2

TPS Watchlist `0.2.2` is a backward-compatible persistence reliability and performance patch. It coalesces superseded queued watch-state snapshots while preserving the released serial ordering, failure visibility, settings boundaries, and durable newest state.

## Changes

- Keep the active state write and at most one newest queued state group instead of reading and rewriting the complete plugin data for every superseded intermediate snapshot.
- Preserve an independent call-time JSON snapshot and promise for every original save request.
- Keep settings writes as hard queue boundaries so state saves never move across a settings mutation.
- If a physical state attempt fails, reject only the oldest original request represented by that attempt. Later original requests retain their own attempt, matching the released failure contract; a successful attempt settles the remaining superseded requests with the newest snapshot.
- Continue reloading current plugin data before every physical state attempt so synchronized settings and unknown top-level fields are preserved.

## Before-and-after evidence

- A deterministic gated overlap submits 100 progressively newer state snapshots while the first write is active.
- Released `0.2.1`: 100 serialized persistence reads and 100 writes.
- Optimized `0.2.2`: two serialized reads and two writes—the active snapshot and the newest queued snapshot—with maximum write concurrency of one and all 100 callers settled.
- Every call still performs its JSON snapshot clone. The measured reduction applies specifically to persistence read/write pairs, not total plugin CPU work or whole-watch wall-clock time.
- Adversarial tests also prove that an active failure does not strand the queued newest state, a one-shot failure of the coalesced tail rejects one caller while later callers persist, and an interleaved settings save produces the exact four expected writes in order.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- Watch behavior, providers, scheduling, notifications, stored data shape, and public API are unchanged.
- The optimization adds no timer, persistent cache, service, schema, monkeypatch, unsupported Obsidian API, or new fallback route.
- Persistent storage failures still surface to callers. Coalescing does not hide an error or create unbounded retries; at most one physical attempt is retained per original save request.
